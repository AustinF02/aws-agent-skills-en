# Set Up and Connect AWS MCP

Confirm the agent, operating system, profile name, workload Region, and existing authentication method. Never request credentials. Explain any required initial browser sign-in and obtain authorization.

## Make the smallest change

- Inspect and test an existing `aws-mcp` entry first. Do not add a duplicate under a different name.
- Locate `uvx` and AWS CLI. When GUI and terminal PATH values differ, use the detected executables' absolute paths.
- Verify the AWS MCP endpoint against current official documentation. The initial example is `https://aws-mcp.us-east-1.api.aws/mcp`. Keep the endpoint Region separate from the workload Region.
- The current official CLI distribution is `mcp-proxy-for-aws-cli@latest`. Explain that it downloads external code. Do not replace arguments generated by Agent Toolkit without establishing the need.
- Set the named profile through `AWS_MCP_PROXY_PROFILES`. Set `AWS_REGION` and `AWS_DEFAULT_REGION` to the user's workload Region. Never redistribute personal account details, profile selections, or machine-specific paths.

Codex example, using illustrative non-secret values that must be replaced with the user's selections:
```toml
[mcp_servers.aws-mcp]
command = "uvx"
args = ["mcp-proxy-for-aws-cli@latest", "https://aws-mcp.us-east-1.api.aws/mcp"]
startup_timeout_sec = 60

[mcp_servers.aws-mcp.env]
AWS_MCP_PROXY_PROFILES = "example-dev"
AWS_REGION = "ap-northeast-1"
AWS_DEFAULT_REGION = "ap-northeast-1"
```

For Kiro, set the corresponding command/args/env fields under `mcpServers.aws-mcp`. For Claude Code, use its official CLI to register a stdio server. Preserve unrelated configuration. Validate syntax and confirm that other entries are unchanged after saving.

## Automate sign-in only when requested

Explain that a browser will open when authentication is needed, then read the available `aws-login-helper` skill. If it is missing, offer the [login helper skill](https://github.com/AustinF02/aws-agent-skills-en/tree/main/skills/aws-login-helper). It supports one profile and must not silently replace a multi-profile configuration.

## Verification and failures

1. Check STS access with the selected profile. Record only success or failure, without printing IDs or ARNs.
2. Verify MCP initialization and tools/list. Do not call tools that modify the account.
3. Distinguish configuration saved, authentication passed, MCP initialized, and verified use inside the actual app.
4. Do not infer the cause from JSON-RPC `Invalid request parameters` alone. Use sanitized evidence to distinguish expired authentication, a missing Region, the wrong profile, and connectivity failures.
5. Do not automatically grant AdministratorAccess or wildcard permissions. After two unsuccessful repair attempts, report the evidence and the next checks.
